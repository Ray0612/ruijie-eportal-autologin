# 六、抓包方法：怎么拿到浏览器真实的登录请求

> **这是整件事的关键一步。**
> 我们花了三个小时在各种参数组合上瞎猜，最后靠抓包 10 分钟就看清了问题。

---

## 6.1 为什么一定要抓包

因为**门户的报错会骗你**。

举个例子，真实的失败响应是：
```json
{"result":"fail","message":"设备未注册,请在ePortal上添加认证设备"}
```

这句话听起来是"学校没给你注册设备"，但实际原因是**你发的 `queryString` 格式不对**。

**⇒ 顺着报错猜，会一路查偏；抓一次真实请求，瞬间就对上了。**

---

## 6.2 ⚠️ 抓包时机很重要

```
✅ 要在【设备真的掉线 / 未认证】的时候抓
      ⇒ 才能拿到"真正登录"那一次 POST

❌ 设备已在线时抓，拿到的只是"重复登录"
      ⇒ 参数可能与首次登录不同，参考价值低
```

---

## 6.3 三种抓法，任选其一

### 方法 A ⭐ 一键抓包代理（最无脑，推荐给不想碰 DevTools 的人）

本项目自带 `tools/capture-proxy.py` + `tools/capture-login.bat`。

**原理**：起一个记录型 HTTP 代理，再用带代理参数的浏览器访问。
- 门户是**明文 HTTP** ⇒ **不需要安装证书**
- HTTPS 流量走 `CONNECT` 隧道直接穿透，不检查、不干扰

**用法（Windows）**：

```
1. 双击 tools/capture-login.bat
2. 会弹出两个窗口：
     ▪ 黑色窗口 = 抓包代理（别关）
     ▪ 一个新的浏览器窗口（已自动配好代理）
3. 在这个新窗口里正常登录
4. 关掉窗口
5. 结果在 captured-requests.txt 里
```

**手动方式（任何系统）**：

```bash
# 1) 起代理
python3 tools/capture-proxy.py

# 2) 另开一个浏览器，指定代理
#    Chrome / Edge:
chrome --proxy-server="127.0.0.1:8899" --user-data-dir=/tmp/capture-profile
```

**优点**：
- **不用在 DevTools 里找具体哪一条请求**
- 自动记录**所有**请求（含请求头、请求体、响应）
- 特别适合"不知道自己该找什么"的情况

---

### 方法 B 保存全部 HAR（Chrome / Edge 自带）

```
1. F12 打开开发者工具
2. 切到 Network（网络）标签
3. 勾选 Preserve log（保留日志）
4. 完成一次登录
5. 【在请求列表里任意位置右键】→ "Save all as HAR with content"
6. 得到一个 .har 文件
```

**优点**：不用挑具体的某一条，全都记下来了。
**缺点**：HAR 是 JSON，要自己翻（可以用 <https://toolbox.googleapps.com/apps/har_analyzer/> 之类的工具打开）。

---

### 方法 C Copy as cURL（最精确）

```
1. F12 → Network → 勾选 Preserve log
2. 完成一次登录
3. 在列表里找到 POST 到 InterFace.do?method=login 的那一条
     （可以按 "login" 过滤，或者按 Method 排序看 POST）
4. 右键它 → Copy → Copy as cURL (bash)
5. 粘贴到文本文件里
```

**优点**：直接就是可执行的命令。
**缺点**：需要会找请求（很多人卡在这一步）。

**拿到 cURL 之后**，可以用本项目自带的转换工具直接生成路由器脚本：

```bash
python3 tools/curl2router.py captured-curl.txt
# 输出 campus-curl.sh（纯 ASCII、LF 行尾、可直接在路由器上跑）
```

## 6.4 抓到以后看什么

### 重点看这四个位置

```
① 请求体（Form Data / --data-raw）
     userId         → 账号的编码方式（是否双重编码？带不带前缀？）
     password       → 明文还是 RSA？（对应 passwordEncrypt）
     queryString    → ⭐⭐⭐ 最重要：整段令牌串是什么样的
     passwordEncrypt → false / true

② 请求头
     Host           → ⚠️ 首字母是大写还是小写？
     Referer        → 带不带令牌串？
     Cookie         → 有哪些？（JSESSIONID / EPORTAL_* 等）

③ 响应体
     {"result":"success","userIndex":"…"}     → 成功时的样子

④ 如果失败过，把失败的响应也留下
     message 字段往往具有误导性，不要只信它
```

### 一个真实的对照示例

**我们一开始是这么发**：
```
queryString=wlanuserip%253D10.0.0.100          ← ❌ 用真实 IP
```

**抓包后发现浏览器是这么发**：
```
queryString=wlanuserip%253Da1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6%2526wlanacname%253D…
                                                                  ↑ 整段令牌，不是 IP
```

**⇒ 差距一目了然。**

## 6.5 安全提示

```
⚠️ 抓包文件里【一定】有你的账号、密码、令牌
   ⇒ 绝对不要提交到 Git
   ⇒ 本项目的 .gitignore 已经把这些文件排除

⚠️ 抓包代理只监听 127.0.0.1
   ⇒ 不要改成 0.0.0.0，否则同一局域网的其他设备也会走你的代理

⚠️ 用完记得关掉代理窗口，并恢复浏览器设置
   （用本项目 .bat 启动的是独立配置目录，关闭即失效，不影响日常浏览器）
```

---

## 6.6 一句话总结

> **不要顺着报错猜参数。抓一次真实成功的请求，逐字段对照，十分钟解决。**
