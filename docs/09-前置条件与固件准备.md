# 九、前置条件与固件准备

> 本项目假设你**能够以 root 身份登录路由器**。
> 如果你用的是官方固件并且 SSH 是关闭的，本文说明怎么打开它。

---

## 9.1 先确认你的情况

```bash
# 试着连一下
ssh root@<路由器IP>
```

| 结果 | 你的情况 | 接下来 |
|---|---|---|
| ✅ 能进 | 已经可以了 | 跳到 [9.5 验证环境](#95-验证环境) |
| ❌ 拒绝连接 / 端口不通 | SSH 关闭 | 看 [9.2](#92-开启-ssh-的几种途径) |
| ❌ 提示密码错误 | 密码不对（不是 SSH 关闭）| 查路由器背面标签或说明书 |

## 9.2 开启 SSH 的几种途径

### 情况 A：已经是 OpenWrt / Padavan / Merlin / DD-WRT

**⇒ 不需要任何额外操作。** 这些固件默认就开着 SSH。

### 情况 B：小米 / Redmi 官方固件

官方固件默认**关闭** SSH。社区有一个成熟的开源工具可以开启：

#### ⭐ [XMiR-Patcher](https://github.com/openwrt-xiaomi/xmir-patcher)

```
Firmware patcher for Xiaomi routers
```

**用途**：为小米 / Redmi 系列路由器开启 SSH（以及可选的更多功能）。

**基本用法**（以其 README 为准）：

```bash
# Windows
run.bat

# Linux / Mac OS
# 需要 python 3.8+ 和 openssl
./run.sh
```

**操作流程（大致）**：

```
1. 把路由器接到电脑，确认能访问它的管理页面
2. 运行 run.bat / run.sh
3. 菜单里选择"开启 SSH"类的选项
4. 按提示完成（通常需要路由器管理密码）
5. 完成后用 ssh root@<路由器IP> 验证
```

> ⚠️ **具体菜单项和步骤请务必以该项目的最新 README / 界面提示为准。**
> 本项目不复制它的操作细节，因为版本更新会变化。

#### ⚠️ 必须先告知用户的风险

在动手之前，请明确告诉用户：

```
① 修改固件会使保修失效
② 操作不当可能导致设备变砖（需要救砖手段）
③ 建议先备份（该工具本身也提供备份功能）
④ 部分型号的开启方式依赖尚未修复的漏洞，厂商固件更新后可能失效
⑤ 如果设备已经在保修期内、且你不能承担变砖风险，就不要做
```

### 情况 C：其它品牌 / 其它固件

思路是一样的，但具体手段因厂商而异：

```
1. 先查该型号是否已有 OpenWrt 官方支持 → 直接刷 OpenWrt 最省事
2. 否则查该厂商的"开启 telnet/ssh"社区方案
3. 如果都不行 ⇒ 本项目不适用，考虑把认证逻辑放到别的设备上
   （PC / 树莓派 / 旧手机 一直开着，替路由器做认证）
```

## 9.3 ⚠️ 一个重要的坑：SSH 可能"这次开了，下次又没了"

有些固件（尤其是官方固件打补丁开启的）**在恢复出厂设置或固件升级后，SSH 会重新关闭**。

**⇒ 建议做一层持久化保险**：

```bash
# 1) 用 nvram 记住开关（如果你的固件有 nvram）
nvram set ssh_en=1
nvram commit

# 2) 用 cron 每分钟检查并重新应用（防止被重置）
cat > /etc/storage/ssh-keepalive.sh <<'EOF'
#!/bin/sh
[ "$(nvram get ssh_en 2>/dev/null)" = "1" ] || { nvram set ssh_en=1; nvram commit; }
/etc/init.d/dropbear running >/dev/null 2>&1 || /etc/init.d/dropbear restart
EOF
chmod +x /etc/storage/ssh-keepalive.sh

echo '*/1 * * * * /etc/storage/ssh-keepalive.sh >/dev/null 2>&1' >> /etc/crontabs/root
/etc/init.d/cron restart
```

> ⚠️ 上面的路径和命令因固件而异（`nvram` / `bdata` / `uci` 各不相同）。
> **请先确认你的固件用哪一套**。

**⇒ 恢复出厂设置后仍然需要重新开启一次，这是无法完全避免的。**

## 9.4 配好 SSH 免密登录（强烈建议）

方便后续部署脚本：

```bash
# 1) 生成专用密钥（不要复用你其它地方的 key）
ssh-keygen -t rsa -b 2048 -f ~/.ssh/id_rsa_router -N ""

# 2) 推到路由器
cat ~/.ssh/id_rsa_router.pub | ssh root@<路由器IP> \
  "mkdir -p /etc/dropbear && cat >> /etc/dropbear/authorized_keys"

# 3) 写 ~/.ssh/config
cat >> ~/.ssh/config <<'EOF'
Host router
    HostName <路由器IP>
    User root
    IdentityFile ~/.ssh/id_rsa_router
    IdentitiesOnly yes
    # 老固件的 dropbear 可能只支持 ssh-rsa
    HostKeyAlgorithms +ssh-rsa
    PubkeyAcceptedAlgorithms +ssh-rsa
    ServerAliveInterval 30
EOF

# 4) 验证
ssh router "echo ok"
```

**⚠️ 如果报 `no matching host key type found`**：说明你的客户端较新、路由器较老。
加上 `HostKeyAlgorithms +ssh-rsa` 即可（已包含在上面的配置里）。

**⚠️ 如果重启后免密失效**：检查 `authorized_keys` 是否在**持久分区**。

## 9.5 验证环境

部署本项目之前，确认下面每一项：

```bash
ssh router '
echo "=== 1. 基本环境 ==="
uname -a
echo
echo "=== 2. curl ==="
command -v curl && curl --version | head -1 || echo "!! 没有 curl"
echo
echo "=== 3. shell ==="
readlink -f /bin/sh; ls -la /bin/sh
echo
echo "=== 4. 持久分区 ==="
mount | grep -E "storage|data|jffs|overlay"
echo
echo "=== 5. WAN 接口 ==="
ip route | grep default
ip -4 addr | grep -E "^[0-9]+:|inet "
echo
echo "=== 6. cron ==="
ls -la /etc/crontabs/ 2>/dev/null || echo "(没有 /etc/crontabs)"
ps | grep -c crond
echo
echo "=== 7. 内存与负载 ==="
free
cat /proc/loadavg
'
```

**逐项确认**：

| # | 检查项 | 期望 |
|---|---|---|
| 1 | 能执行 `uname -a` | 看到内核版本 |
| 2 | `curl` 存在 | 有路径输出 |
| 3 | `/bin/sh` | 通常是 busybox 的软链 |
| 4 | 有持久分区 | 看到 `/etc/storage` 或 `/data` 等 |
| 5 | 有默认路由 + WAN 有 IP | 看到 `default via …` |
| 6 | crond 在跑 | 有进程 |
| 7 | 空闲内存 | **至少 30 MB**（低于此要谨慎）|

## 9.6 关于"把认证放到别的设备上"

**如果路由器实在搞不定**（没有 SSH / 没有 curl / 内存太小 / 固件太老），
还有一个稳妥的替代方案：

```
找一台【长期开着的、能装 Python 的】设备（旧手机、树莓派、NAS、PC），
让它连在路由器下面，由它来完成认证。
```

**为什么可行**：门户是基于**源 IP** 判断的。那台设备发出的认证请求，
同样经过路由器的 WAN 出去，门户看到的是**路由器的 WAN IP** —— 与路由器自己发起效果相同。

**现成的实现**（都是 PC 端，Python/C#/Go）：

- [LFWQSP2641/scu_net_auto_login](https://github.com/lfwqsp2641/scu_net_auto_login)
- [Redlnn/Ruijie-ePorta-Tool](https://github.com/Redlnn/Ruijie-ePorta-Tool)
- [evin546/SCUNETAssistant](https://github.com/evin546/SCUNETAssistant)

**⚠️ 注意**：这些项目的参数格式可能对应**较老的门户版本**。
用之前请按 [06-抓包方法.md](06-抓包方法.md) 核对你学校的实际情况。

□ （可选）已配置 SSH 免密登录
