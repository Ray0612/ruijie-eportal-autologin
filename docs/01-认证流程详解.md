# 一、锐捷 ePortal 认证流程详解

> 本文描述锐捷 ePortal 网页认证的**完整技术流程**，是后续所有文档的基础。
>
> ⚠️ 不同学校部署的门户版本不同，**具体字段可能有差异**。请以自己的抓包结果为准。

---

## 1.1 整体流程

```
  设备                         接入设备(AC)                   ePortal 门户
   │                                │                              │
   │ ① 发起任意 HTTP 请求            │                              │
   │───────────────────────────────>│                              │
   │                                │  ② 未认证 ⇒ 拦截              │
   │                                │─────────────────────────────>│
   │ ③ 返回 JS 跳转页（带令牌串）    │                              │
   │<──────────────────────────────────────────────────────────────│
   │                                                               │
   │ ④ GET /eportal/index.jsp?<令牌串>                              │
   │──────────────────────────────────────────────────────────────>│
   │ ⑤ 返回登录页 HTML + JS                                        │
   │<──────────────────────────────────────────────────────────────│
   │                                                               │
   │ ⑥ POST InterFace.do?method=pageInfo    （取公钥/配置）          │
   │──────────────────────────────────────────────────────────────>│
   │                                                               │
   │ ⑦ POST InterFace.do?method=login       （提交账号密码）         │
   │──────────────────────────────────────────────────────────────>│
   │ ⑧ {"result":"success","userIndex":"…"}                        │
   │<──────────────────────────────────────────────────────────────│
   │                                                               │
   │ ⑨ 网络放行 ✅                                                  │
```

---

## 1.2 端点一览

设门户地址为 `<门户>`（例如 `10.0.0.1`）。

| 端点 | 方法 | 作用 | 是否需要 `queryString` |
|---|---|---|---|
| `<门户>/eportal/index.jsp` | GET | 登录页（URL 里带令牌串）| 令牌串在 URL 里 |
| `<门户>/eportal/InterFace.do?method=pageInfo` | POST | **取配置**：`passwordEncrypt`、RSA 公钥、验证码开关、账号前缀 | ✅ 需要 |
| `<门户>/eportal/InterFace.do?method=getServices&queryString=…` | POST | 取可选服务出口（教育网/电信/联通/移动）| URL 里带 |
| `<门户>/eportal/InterFace.do?method=login` | POST | **登录** | ✅ 需要 |
| `<门户>/eportal/InterFace.do?method=logout` | POST | 下线（`userId=<编码后账号>`）| ❌ |
| `<门户>/eportal/InterFace.do?method=getOnlineUserInfo` | POST | 查询在线信息 | ❌ |
| `<门户>/userV2.do?method=getErrorMsg` | POST | 取错误信息 | ❌ |
| `<门户>/eportal/success.jsp?userIndex=…` | GET | 认证成功后的落地页 | ❌ |

## 1.3 `pageInfo` 返回的字段（重要）

```json
{
  "passwordEncrypt": "false",
  "publicKeyExponent": "10001",
  "publicKeyModulus": "0123456789abcdef…（256 字符）",
  "validCodeUrl": "",
  "prefixName": "false",
  "prefixValue": "",
  "service": {},
  "loginText": "某某网络认证",
  "announcement": "<span>…系统通知…</span>",
  "selfUrl": "http://<自助服务地址>",
  "isForgetPassword": "true",
  "isAutoLogin": "false"
}
```

| 字段 | 含义 | 对脚本的影响 |
|---|---|---|
| **`passwordEncrypt`** | 服务器期望的密码格式 | ⭐ **`false`=明文，`true`=RSA**（见 [坑 2](03-passwordEncrypt语义.md)）|
| `publicKeyExponent` / `publicKeyModulus` | RSA 公钥 | ⚠️ **只有 `passwordEncrypt=true` 时才需要** |
| **`validCodeUrl`** | 图形验证码图片地址 | ⭐ **非空 ⇒ 必须填验证码**（通常是失败次数过多才触发）|
| `prefixName` / `prefixValue` | 账号前缀 | 若 `prefixName=true`，`userId` 要拼上前缀 |
| `service` | 可选服务出口列表 | 部分学校要选（教育网/电信等）|

**⭐ 重要特性：`pageInfo` 是"静态"的。**
不管 `queryString` 传什么（真实令牌 / 空 / 乱填），返回的配置都一样。
**⇒ 不要指望靠它区分连接状态。**

## 1.4 登录请求的完整格式

```http
POST http://<门户>/eportal/InterFace.do?method=login HTTP/1.1
Host: <门户>                                                   ← ⚠️ 首字母大写
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Accept: */*
Origin: http://<门户>
Referer: http://<门户>/eportal/index.jsp?<令牌串>
Accept-Encoding: gzip, deflate
Accept-Language: zh-CN,zh;q=0.9
Cookie: EPORTAL_USER_GROUP=…; JSESSIONID=…
Content-Length: <长度>

userId=<账号，URL 双重编码>
&password=<见 passwordEncrypt>
&service=<URL 双重编码，通常空>
&queryString=<⭐ 整段令牌串的 URL 双重编码>
&operatorPwd=
&operatorUserId=
&validcode=<验证码，通常空>
&passwordEncrypt=<false 或 true>
```

### 成功响应

```json
{
  "userIndex": "3031323334353637...",
  "result": "success",
  "message": "",
  "forwordurl": null,
  "keepaliveInterval": 0,
  "validCodeUrl": ""
}
```

### `userIndex` 的结构

`userIndex` 是 **十六进制字符串**，解码后是：

```
<nasip令牌>_<客户端IP>_<账号>
```

例：
```
hex  : 3031323334656661626364...      （此处为示意）
ascii: 0123456789abcdef_10.0.0.100_USER@domain
```

**⇒ 这个结构可以用来验证"登录的到底是谁、从哪个 IP"。**

---

## 1.5 失败响应（重点）

```json
{
  "userIndex": null,
  "result": "fail",
  "message": "设备未注册,请在ePortal上添加认证设备",
  "forwordurl": null,
  "keepaliveInterval": 0,
  "validCodeUrl": ""
}
```

**⚠️ 这句话极其误导。** 它听起来像"学校没给你注册设备"，
但**在我们这个案例里，真实原因是 `queryString` 格式不对**。

详见 [02-queryString令牌陷阱.md](02-queryString令牌陷阱.md)。

## 1.6 用 curl 手工验证流程

```bash
# ── 变量 ──
PORTAL="10.0.0.1"
ACCOUNT="YOUR_ACCOUNT"          # 按需做 URL 编码
PASSWORD="YOUR_PASSWORD"
QS_RAW='wlanuserip=0123456789abcdef0123456789abcdef&wlanacname=0123456789abcdef&ssid=fedcba9876543210&nasip=abcdef0123456789abcdef0123456789&mac=00112233445566778899aabbccddeeff&t=wireless-v2'

# ── 双重 URL 编码（% 必须先转义，跑两遍）──
_enc1() { sed -e 's/%/%25/g' -e 's/@/%40/g' -e 's/&/%26/g' -e 's/=/%3D/g' -e 's/?/%3F/g' -e 's/+/%2B/g' -e 's/ /%20/g'; }
enc2()  { printf '%s' "$1" | _enc1 | _enc1; }

QS=$(enc2 "$QS_RAW")
UID=$(enc2 "$ACCOUNT")

# ── 1) 取配置 ──
curl -s -X POST -d "queryString=$QS" \
  "http://$PORTAL/eportal/InterFace.do?method=pageInfo"

# ── 2) 登录（假设 passwordEncrypt=false ⇒ 明文）──
curl -s -X POST \
  -H "Host: $PORTAL" \
  -H "Content-Type: application/x-www-form-urlencoded; charset=UTF-8" \
  -H "Origin: http://$PORTAL" \
  -H "Referer: http://$PORTAL/eportal/index.jsp?$QS_RAW" \
  --data-raw "userId=$UID&password=$PASSWORD&service=&queryString=$QS&operatorPwd=&operatorUserId=&validcode=&passwordEncrypt=false" \
  "http://$PORTAL/eportal/InterFace.do?method=login"
```
