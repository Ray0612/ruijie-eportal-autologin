# 八、门户前端源码分析

> 本文是对锐捷 ePortal **登录页前端代码**的分析笔记。
>
> ⚠️ **重要声明**：门户前端代码是厂商的**专有代码**，不是开源项目。
> 本文**不包含**原始文件，只引用关键片段作为技术分析依据。
> 如果你需要自己分析，请按 [06-抓包方法.md](06-抓包方法.md) 抓到**你自己学校**的版本。

---

## 8.1 怎么拿到你自己学校的前端代码

登录页会加载 3 个 JS 文件，浏览器直接请求它们：

```
<门户>/eportal/index.jsp                                  ← 页面本身
<门户>/eportal/interface/index_files/js/AuthInterFace.js   ← 接口层
<门户>/eportal/interface/index_files/pc/login_bch.js      ← 登录逻辑
<门户>/eportal/interface/index_files/js/security.js       ← RSA 实现
```

**用 `curl` 直接下（把 `<门户>` 换成你自己的）：**

```bash
PORTAL=10.0.0.1
mkdir -p portal-src && cd portal-src

for f in \
  "eportal/InterFace.do?method=pageInfo" \
  "eportal/interface/index_files/js/AuthInterFace.js" \
  "eportal/interface/index_files/pc/login_bch.js" \
  "eportal/interface/index_files/js/security.js"
do
  out=$(echo "$f" | tr '/?=&' '____')
  curl -s "http://$PORTAL/$f" -o "$out"
  echo "$out  $(wc -c < "$out") bytes"
done
```

> ⚠️ 有些门户会对 `index.jsp` 做重定向，需要带上正确的 `queryString` 才能拿到登录页。

**⚠️ 这些文件里会包含你学校的名称、门户地址等信息。
分析完请自行删除，不要提交到任何仓库。**

## 8.2 三个文件的分工

```
index.jsp
   │  页面骨架 + 内联脚本
   │  负责：把 pageInfo 返回的配置"贴"到表单里
   ▼
login_bch.js
   │  登录逻辑（点击登录按钮之后的事）
   │  负责：校验表单、编码参数、调接口
   ▼
AuthInterFace.js
   │  接口封装层
   │  负责：拼请求体、POST、回调
   ▼
security.js
       RSA 实现（经典 security.js 的 RSAUtils）
```

---

## 8.3 `AuthInterFace.js` —— 接口层（**信息量最大**）

这个文件把门户所有的 AJAX 端点都列出来了。**建议先读它。**

### 关键片段（登录方法的签名）

```js
login : function(userId, password, service, queryString,
                 operatorPwd, operatorUserId, validcode,
                 passwordEncrypt, callback) {
    ...
}
```

**⇒ 一眼就能看出登录需要哪些字段。**

### 关键片段（密码的两个分支）

```js
var passwordEncrypt = encodeURIComponent(encodeURIComponent(
    document.getElementById("passwordEncrypt").value));

if (passwordEncrypt && passwordEncrypt == "true") {
    password = encryptedString(key, password);
} else {
    password = RSAUtils.encryptedString(key, password.split("").reverse().join(""));
}
```

**⇒ 这里是最容易误判的地方**：
看起来两个分支都做了 RSA，但实测 `passwordEncrypt=false` 时
`RSAUtils` 往往未加载，**实际发出去的是明文**。

详见 [03-passwordEncrypt语义.md](03-passwordEncrypt语义.md)。

### 完整端点表（从该文件归纳）

| 方法名 | 作用 |
|---|---|
| `login` | 登录 |
| `logout` | 下线 |
| `logoutByUserIdAndPass` | 用账号密码下线 |
| `keepalive` | 心跳保活 |
| `getOnlineUserInfo` / `freshOnlineUserInfo` | 在线信息 |
| `pageInfo` | 取配置（公钥、验证码开关、账号前缀）|
| `getServices` | 取可选服务出口 |
| `switchService` | 切换出口 |
| `registerMac` | 注册 MAC（**与"无感知认证"相关**）|
| `cancelMac` / `cancelMacWithUserNameAndMac` | 取消 MAC 注册 |
| `loginWithQrCode` | 扫码登录 |
| `loginWithSmsVerifyCode` | 短信验证码登录 |
| `visitorReg` / `visitorSmsAuth` | 访客注册 |
| `modifyPass` | 改密码 |
| `validateUserName` | 校验用户名 |
| `registerNetWorkProtocol` | 注册网络协议 |

**⭐ 值得注意的**：`registerMac` / `cancelMac` 说明门户**原生支持 MAC 绑定**。
这就是"无感知认证"的实现基础 —— 如果你的学校关闭了这个功能，
那么脚本就只能老老实实走"账号密码登录"这条路。

## 8.4 `login_bch.js` —— 登录逻辑（**编码规则在这里**）

### 关键片段（三重编码，最容易漏）

```js
var queryString = encodeURIComponent(encodeURIComponent(getQueryString()));
var userId      = encodeURIComponent(encodeURIComponent(username));
...
var password    = encodeURIComponent(encodeURIComponent(password));
...
AuthInterFace.login(userId, password, service, queryString, ...);
```

**⇒ 三个字段都要做【两次】`encodeURIComponent`。**

**⚠️ 这也是很多人失败的地方**：只做一次编码，门户解析不了。

### 关键片段（验证码开关）

```js
var validCodeUrl = pageInfo.validCodeUrl;
if (validCodeUrl != '') {
    $("#validImage").attr("src", validCodeUrl);
    $("#isDisplayValidCode").show();      // 显示验证码输入框
}
```

**⇒ `pageInfo.validCodeUrl` 非空 ⇒ 必须填验证码。**
（通常是登录失败次数过多才会触发。）

### 关键片段（账号前缀）

```js
var prefixValue = pageInfo.prefixValue;
...
username = prefixValue + username;
```

**⇒ 如果 `pageInfo.prefixName == "true"`，账号要拼上前缀。**

### 关键片段（MAC 参数）

```js
var macString = getQueryStringByName("mac");
if (isNull(macString)) {
    macString = "111111111";
}
```

**⇒ 说明某些学校的 `queryString` 里会带 `mac` 参数。**

## 8.5 `index.jsp` —— 页面骨架

主要作用是：拿到 `pageInfo` 之后，把配置写到隐藏表单域里。

```js
if (pageInfo.passwordEncrypt && pageInfo.passwordEncrypt == "true") {
    $("#passwordEncrypt").attr("value", "true");
}
$("#publicKeyExponent").attr("value", pageInfo.publicKeyExponent);
$("#publicKeyModulus").attr("value", pageInfo.publicKeyModulus);
```

**⇒ 这就是"公钥从 `pageInfo` 来"的直接证据。**

## 8.6 `security.js` —— RSA 实现

它是经典的 `RSAUtils`（网上能搜到大量同名实现），关键特性：

```js
this.chunkSize = 2 * biHighIndex(this.m);        // 1024 位密钥 => 126 字节
while (a.length % chunkSize != 0) a[i++] = 0;    // 纯零填充，无 PKCS#1 头
block.digits[j] = a[k++] + (a[k++] << 8);        // 小端 16 位一组
crypt = block ^ e mod m;                         // 教科书 RSA
text  = biToHex(crypt);                          // 每 16 位输出 4 个 hex
result = texts.join(" ");                        // 多块用空格分隔
```

**⇒ 这是「教科书式 RSA（零填充）」，不是 PKCS#1 v1.5。**

**⚠️ 如果用 openssl 实现，必须关掉填充**：
```bash
openssl pkeyutl -encrypt -pkeyopt rsa_padding_mode:none …
```

**⚠️ 并且密码要先做 `split("").reverse().join("")` —— 字符串反转。**

## 8.7 从源码里能确认的 5 条结论

| # | 结论 | 出处 |
|---|---|---|
| 1 | 登录端点就是 `InterFace.do?method=login` | `AuthInterFace.js` |
| 2 | `userId` / `password` / `queryString` **都要双重编码** | `login_bch.js` |
| 3 | 公钥来自 `pageInfo`，不是写死在页面里 | `index.jsp` |
| 4 | `passwordEncrypt=false` 时**实际是明文** | `AuthInterFace.js` + 抓包对照 |
| 5 | 门户原生支持 MAC 注册（`registerMac`），即"无感知认证" | `AuthInterFace.js` |
