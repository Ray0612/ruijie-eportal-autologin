# 七、故障排查表

> 按"你看到的报错"查原因。**请先读第 1 条** —— 90% 的人都栽在它上面。

---

## 7.0 快速自查清单

动手之前，先确认这几件事：

```
□ 抓过包了吗？拿到浏览器真实成功的请求了吗？
□ queryString 是从门户拦截页【整段抓】的，不是自己拼的？
□ userId / queryString 做了【双重】URL 编码？
□ Host 首字母是大写？
□ passwordEncrypt 是从 pageInfo 读的，不是猜的？
□ 探测间隔 ≥ 120 秒（建议 300）？
□ 脚本是纯 ASCII + LF 行尾？
```

## 7.1 登录相关

### ❌ `设备未注册,请在ePortal上添加认证设备`

**⭐ 这是最高频、也最误导的一个。**

| 可能原因 | 概率 | 处理 |
|---|---|---|
| **`queryString` 格式不对** | **90%** | ⭐ 改成从门户拦截页**整段抓**（见 [坑 1](02-queryString令牌陷阱.md)）|
| 只发 `wlanuserip`，漏了 `wlanacname`/`ssid`/`nasip`/`mac`/`t` | 高 | 同上，整段抓 |
| `wlanuserip` 用的是真实 IP，不是令牌 | 高 | 同上 |
| 令牌里的十六进制被正则截断了 | 高 | 检查你的 `sed` 是否只匹配数字和点 |
| 校园侧的"设备注册状态"失效 | 中 | 在浏览器里认证一次重新激活 |
| 设备真没在门户上登记 | 低 | 联系网络管理员 |

**⇒ 排查顺序：先怀疑参数格式，再怀疑设备注册。**

### ❌ `用户名不能为空`

```
原因：请求体没拼对 / 为空 / Content-Length 不对
处理：检查 --data-raw 的内容；用 curl -v 看实际发出去的 body
```

### ❌ `用户名或密码错误`

```
原因 A：passwordEncrypt 与 password 实际格式不匹配
        （该发明文时发了 RSA，或反过来）
处理 A：调一次 pageInfo，确认 passwordEncrypt 的实际值

原因 B：账号需要带后缀（@域名）或前缀
处理 B：看 pageInfo 的 prefixName / prefixValue

原因 C：密码真的错了
```

### ❌ 响应里突然多了 `"validCodeUrl":"http://…（非空）"`

```
原因：登录失败次数过多，门户开启了图形验证码
处理：
  ① 立刻停手，别再试
  ② 隔 10~30 分钟再试
  ③ 用浏览器手工认证一次，重置状态
  ④ 之后务必一次成功，别反复试错
```

### ❌ TCP 连接直接被断开（没有 HTTP 响应）

```
原因：Host 请求头写成了小写（部分锐捷门户会检查大小写）
处理：确保是 "Host: xxx"（首字母大写）

⚠️ 有些 HTTP 库会自动把请求头键名转小写
   （例如 Qt 的 QNetworkAccessManager）
   ⇒ 那就必须手工构造 HTTP 请求，或者换 curl
```

### ❌ 返回 404 / 502

```
原因：URL 路径写错（注意是 eportal 还是 ePortal，大小写不同）
处理：以抓包结果为准，逐字符对照
```

## 7.2 脚本部署相关

### ❌ 脚本起来了但立刻退出，日志只有启动那一行

```
原因：行尾是 CRLF，导致 #!/bin/sh\r 找不到解释器
检查：od -c 脚本 | head -2      （看有没有 \r）
处理：dos2unix 脚本   或   sed -i 's/\r$//' 脚本
```

### ❌ 中文注释乱码 / 出现奇怪字符

```
原因：固件没有 locale，按字节处理
处理：脚本【必须纯 ASCII】
      检查：tr -d '\0-\177' < 脚本 | wc -c    （应为 0）
```

### ❌ `setsid: not found` / `nohup: not found`

```
原因：固件精简掉了
处理：用 & 后台化，或者改用"cron 每分钟检查 + 自检存活"的看门狗方式
      （见 router/start.sh）
```

### ❌ cron 加了 `@reboot` 但开机不执行

```
原因：很多 busybox cron 不支持 @reboot
处理：改成 * * * * * + 自检：
      * * * * * /path/start.sh
      而 start.sh 里判断"如果没在跑就启动"
```

### ❌ 脚本/配置重启就丢

```
原因：放在了 tmpfs（如 /tmp）
处理：放到持久分区。常见位置因固件而异：
      /etc/storage   /data   /jffs   /overlay
      先用 mount 或 df 确认
```

## 7.3 路由器异常重启

### ❌ 每隔几分钟就重启一次，日志里没有关机过程

**⭐ 这几乎一定是「轮询太频繁把设备压垮 ⇒ 硬件看门狗静默复位」。**

详见 [坑 3](04-嵌入式设备轮询陷阱.md)。

**快速自查**：
```sh
# 1) 数一下重启间隔
cat /etc/storage/diag/reboots.log

# 2) 看探测间隔是多少
grep '^INTERVAL=' /etc/storage/campus/campus-login.sh

# 3) 临时停掉脚本，观察是否还重启
kill $(pgrep -f campus-login.sh)
```

**处理**：
```
① INTERVAL 改到 300
② 加零流量前置判断
③ 在线时不写日志
```

### ❌ 内存看起来不够 / 进程数暴涨

```
检查：free; ps | wc -l
处理：减少 fork（别每轮都调 date/wc/tail/curl 之外的命令）
```

## 7.4 诊断命令速查

```sh
# ── 当前状态 ──
cat /proc/sys/kernel/random/boot_id      # 每次启动唯一 ⇒ 数重启
cat /proc/uptime                          # 已运行秒数
free                                      # 内存
cat /proc/loadavg                         # 负载
ps | wc -l                                # 进程数

# ── 网络 ──
ip -4 addr show                           # 接口地址
ip route                                  # 默认路由
cat /sys/class/net/<接口>/operstate       # 链路状态（up/down）
cat /sys/class/net/<接口>/statistics/rx_errors

# ── 在线判定 ──
curl -s -o /dev/null -w '%{http_code}\n' http://<探测地址>
curl -s -i http://<探测地址> | head -20   # 看是否被劫持

# ── 进程 ──
pgrep -f campus-login.sh                  # 找 PID
ps | grep campus-login

# ── 日志 ──
tail -50 /tmp/campus-login.log            # ⚠️ 这个重启会丢
tail -50 /etc/storage/diag/heartbeat.log  # 持久
tail -50 /etc/storage/diag/reboots.log    # 持久

# ── cron ──
cat /etc/crontabs/root
ps | grep crond
/etc/init.d/cron running
```

## 7.5 ⚠️ 一个通用忠告

```
不要把门户的 message 字段当唯一线索。
   "设备未注册" 可能是参数格式错；
   "用户名或密码错误" 可能是编码方式错。

⭐ 唯一可靠的定位方式：
   抓一次浏览器【真实成功】的请求，然后逐字段对照你的脚本。
```
